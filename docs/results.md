| 指标 | 核验结果 | 含义 |
|---|---:|---|
| 接受的示教回合 | 60 | 经筛选的训练候选，不是所有尝试的成功率分母 |
| 不同 seed | 59 | seed 10 有两条轨迹，均在训练侧 |
| 训练 / 验证回合 | 50 / 10 | seed 无交集 |
| 训练 / 验证帧 | 62,779 / 13,747 | 合计 76,526 |
| 原始帧 | 100,211 | 20 Hz 记录 |
| 压缩后帧 | 76,526 | 保留全部非等待帧 |
| 移除的稳定等待帧 | 23,685（23.64%） | 不是采摘成功率或训练效果提升 |
| JPEG 字节核验 | 153,052 张全部匹配 | 两路相机，每帧两张 |
| 回合边界动作块检查 | 600 项 | 导出验证未发现跨回合动作泄漏 |

等待压缩后数据时长从约 83.51 分钟降为 63.77 分钟，减少约 19.74 分钟。只处理 `model_wait` 和 `decision_settle`，稳定区间两端各保留 3 帧，关节、TCP、底盘、果实和命令需满足稳定阈值；接触和连接状态也需保持一致。详细阈值保存在[机器可读汇总](evidence/data-summary.json)。

数据包含 **39 条 v22、21 条 v23** 场景轨迹。v23 改变了成熟果沿行分布，因此不同版本的历史结果不能直接视作同一测试集上的算法对比。固定的验证 seed 为 `1, 2, 9, 14, 26, 32, 42, 43, 44, 56`。

## 4. 后续闭环评估方案

以下是计划，不是已取得的实验结果：

1. 固定场景版本、控制器提交、模型／检查点与推理配置。
2. 预先登记与训练、验证不重叠的测试 seed，避免看结果后选测试场景。
3. 对同一组场景分别运行视觉／工具控制器与 ACT，保留失败、中断和超时，并注明二者的观测与动作接口差异。
4. 以独立环境验收统计单成熟果投筐及返回成功次数，报告分子、分母；服务错误和运行中断单列，说明是否计入主指标。
5. 报告任务耗时、动作阶段失败类型；视觉／工具控制器另报模型调用次数。区分仿真时间、实际墙钟时间和模型等待时间。

若比较“是否等待压缩”的训练收益，需要使用相同 seed 划分、训练预算及闭环评估协议重新训练对照组。当前只能确认帧数减少，尚不能声称策略性能提升。
